# Blender Render Service (этапы 1–3: бэкенд, версии, интерфейс)

Локальный сервис удалённого рендера. Загружаешь `.blend` или `.zip` с текстурами, сервер сам выбирает версию Blender, проверяет проект, ставит рендер в очередь, показывает прогресс и превью кадров, потом отдаёт результат.

Интерфейс на `/` сделан в стиле Marathon: чёрный фон, кислотно-зелёный, шрифты Tektur (заголовки) и Martian Mono (текст). Анимация: поле символов в шапке, полоса прогресса из тех же символов, рамки трекинга поверх превью во время рендера. При включённом в системе «уменьшении движения» анимации отключаются.

Шрифты лежат в `renderservice/static/fonts/` вместе с лицензиями (SIL OFL), интернет для интерфейса не нужен.

## Этапы

0. **Прототип в консоли** (готово). Скрипт, который запускает Blender нужной версии, включает GPU, рендерит тестовый .blend и парсит прогресс. Здесь главные технические риски, поэтому начали именно с него.
1. **Бэкенд MVP** (готово). Загрузка, preflight, очередь, воркер, статусы, скачивание результата.
2. **Фронтенд** (готово). Страница загрузки, очередь, прогресс, превью, кнопка скачивания, отмена.
3. **Менеджер версий** (готово). Определение версии по файлу, скачивание и кеш версий, ближайшая установленная версия как запасная.
4. **Аддоны и текстуры**. Библиотека аддонов, перенос настроек Blender, первичная настройка, zip, отчёт о пропавших файлах (отчёт и zip уже работают).
5. **Финиш**. Автоочистка (готово), страница с инструкцией (готово), автозапуск через systemd (готово, см. ниже), токен-авторизация.
6. **Потом** (масштабирование). Docker, пользователи, несколько воркеров, хранение версий.

## Установка (Arch)

```bash
sudo pacman -S nvidia-utils xorg-server-xvfb
cd render-service
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Версии Blender лежат в одной папке, по умолчанию `~/Applications/blender/`. Каждая версия в своей подпапке (так, как распаковывается официальный архив, например `blender-4.5.12-linux-x64/`). Подробности в разделе «Версии Blender» ниже.

## Запуск

```bash
python run.py
```

Открой `http://localhost:8000`. С других устройств в сети: `http://АДРЕС_ПК:8000`.

Внимание: у сервиса нет авторизации. По умолчанию он слушает всю локальную сеть (`RENDER_HOST=0.0.0.0`). Для доступа только с этого ПК запусти с `RENDER_HOST=127.0.0.1`.

## Автозапуск (systemd)

Чтобы не запускать `python run.py` вручную, сервис ставится как пользовательская служба systemd:

```bash
deploy/install-service.sh
sudo loginctl enable-linger $USER
```

Скрипт записывает юнит `~/.config/systemd/user/blender-render.service` с путями к этой папке и её `.venv`, включает и запускает службу. Вторая команда нужна один раз: без неё пользовательские службы стартуют только после входа в систему, а с ней сразу при загрузке ПК. После этого сайт доступен по `http://АДРЕС_ПК:8000` всегда, пока ПК включён.

Управление:

```bash
systemctl --user status blender-render
systemctl --user restart blender-render
systemctl --user stop blender-render
journalctl --user -u blender-render -f
```

Настройки (папка Blender, порт и т. д.) берутся из `.env` рядом с `run.py`, после правки перезапусти службу. Если сервис упал или ПК перезагрузился во время рендера, задача сама вернётся в очередь и продолжится.

Docker здесь не нужен: рендер идёт прямо на видеокарте этого ПК, а контейнер добавил бы только настройку доступа к GPU и путей к Blender. Он станет полезен на этапе 6, если сервис придётся ставить на другие машины.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `RENDER_BLENDER_ROOT` | `~/Applications/blender` | папка с версиями Blender |
| `RENDER_DATA` | `./data` | где хранятся проекты, рендеры и база |
| `RENDER_HOST` / `RENDER_PORT` | `0.0.0.0` / `8000` | адрес сервера |
| `RENDER_RESULT_DAYS` | `30` | через сколько дней удалять задачу целиком |
| `RENDER_PROJECT_DAYS` | `3` | через сколько дней после рендера удалять файлы проекта (результат остаётся) |
| `RENDER_MAX_UPLOAD_GB` | `0` (без лимита) | максимальный размер загрузки |
| `RENDER_XVFB` | `auto` | `auto`, `true`, `false`: виртуальный экран для EEVEE |
| `RENDER_AUTO_INSTALL` | `true` | скачивать нужную версию Blender автоматически, если её нет |
| `RENDER_DOWNLOAD_BASE` | `https://download.blender.org/release/` | откуда качать Blender |

Настройки можно не передавать в командной строке, а записать в файл `.env` рядом с `run.py` (строки вида `RENDER_BLENDER_ROOT=/mnt/disk/blender`). Переменные окружения важнее файла.

Пример: `RENDER_PORT=9000 RENDER_PROJECT_DAYS=7 python run.py`

## Версии Blender

- Поиск. Сервер ищет Blender в `RENDER_BLENDER_ROOT`: в самой папке и в любой её подпапке (кроме скрытых). Если имя подпапки вида `blender-X.Y.Z-...`, версия берётся из имени, иначе сервер спрашивает её у самого Blender (`blender --version`). Перезапуск после добавления версии не нужен.
- Выбор версии. Берётся последняя установленная версия той же серии, что и проект (например, проект из 4.5 рендерится на 4.5.12). Если такой серии нет, берётся ближайшая более новая, а в задаче появляется предупреждение.
- Автоскачивание. Если серии проекта нет в папке, сервер при проверке проекта скачивает последнюю версию этой серии с download.blender.org, сверяет контрольную сумму SHA-256, распаковывает в `RENDER_BLENDER_ROOT` и продолжает. Прогресс виден на карточке задачи. Если скачать не удалось (нет сети, нет такой версии), используется ближайшая установленная версия с предупреждением. Отключить: `RENDER_AUTO_INSTALL=false`.
- Меню. На главной странице раздел «Версии Blender»: список серий и последних версий, кнопки «Скачать» и «Удалить», прогресс скачивания. Свободного места нужно не меньше 3 ГБ, одна установленная версия занимает около 1 ГБ.
- Поддерживаются серии с 2.93 (сборки Linux x64 с blender.org).

## Как это работает

1. Загрузка. `.blend` кладётся как есть, `.zip` распаковывается с сохранением структуры папок (относительные пути к текстурам продолжают работать). Если в архиве несколько `.blend`, сервис просит выбрать нужный.
2. Проверка (preflight). Определяется версия проекта, подбирается Blender: та же серия, иначе ближайшая более новая, с предупреждением. Blender без рендера читает проект и возвращает движок, разрешение, сэмплы, кадры, формат и список пропавших файлов. Проверка идёт параллельно с рендером, поэтому она может ненадолго замедлить его и занять память.
3. Запуск. Режим «Кадр» или «Анимация» (по умолчанию выбирается по диапазону кадров), устройство OPTIX, CUDA или CPU, при необходимости номер кадра или диапазон `1:100`. Настройки рендера берутся из проекта. Если не найдены файлы, нужно явно подтвердить запуск.
4. Рендер по одной задаче за раз, остальные ждут в очереди. Скрипты проекта не запускаются (`--disable-autoexec`).
5. Прогресс: кадр, сэмпл, оставшееся время, процент, превью готовых кадров.
6. Результат лежит в `data/jobs/<id>/renders/`. Скачивание: один файл отдаётся как есть, несколько кадров одним zip.
7. Отмена, продолжение. «Продолжить» после отмены или сбоя дорисовывает недостающие кадры (для последовательностей картинок). Если сервер перезапустили во время рендера, задача сама вернётся в очередь и продолжит.
8. Очистка раз в час: файлы проекта удаляются через `RENDER_PROJECT_DAYS`, вся задача через `RENDER_RESULT_DAYS`.

## API

`GET /api/status` (что рендерится, длина очереди, место на диске), `GET /api/jobs`, `POST /api/jobs` (файл в поле `file`), `GET /api/jobs/{id}`, `POST /api/jobs/{id}/select`, `POST /api/jobs/{id}/start`, `POST /api/jobs/{id}/cancel`, `DELETE /api/jobs/{id}`, `GET /api/jobs/{id}/download`, `GET /api/jobs/{id}/log`, `GET /api/jobs/{id}/events` (SSE), `GET /api/jobs/{id}/previews/{имя}`, `GET /api/blenders` (установленные версии), `GET /api/blenders/catalog` (установленные, доступные для скачивания и текущие загрузки), `POST /api/blenders/download` (`{"version": "4.5"}` или `{"version": "4.5.12"}`), `DELETE /api/blenders/{версия}`, страница-инструкция `GET /guide`.

Пример запуска из консоли:

```bash
curl -F file=@test.blend http://localhost:8000/api/jobs
curl -X POST -H 'Content-Type: application/json' -d '{"mode":"animation","frames":[1,3]}' http://localhost:8000/api/jobs/ID/start
```

## Что проверить на настоящем Blender

1. Запусти сервис, загрузи `test.blend`, дождись статуса «готов» и убедись, что движок, разрешение и сэмплы показаны верно.
2. Запусти анимацию с диапазоном `1:3`: должны расти кадры, сэмплы, оставшееся время, появляться превью, а скачивание давать zip из трёх кадров.
3. Запусти рендер одного кадра: скачивается одна картинка.
4. Во время рендера нажми «Отменить»: процесс Blender должен исчезнуть (`pgrep -a blender`), потом «Продолжить» должен доделать кадры.
5. Останови сервер (Ctrl+C) во время рендера и запусти снова: задача должна продолжиться сама.
6. Загрузи zip с проектом и текстурами в подпапке: в проверке не должно быть пропавших файлов.
7. Проект на EEVEE: если не стартует, запусти `RENDER_XVFB=true python run.py`.
8. Версии: открой «Версии Blender», нажми «Обновить список», затем скачай любую небольшую старую серию (например, 3.6) и проверь, что она появилась в папке и в списке. Потом загрузи проект, сохранённый в серии, которой нет на диске: сервер должен сам скачать её.

Если список версий пустой или скачивание падает, на ПК с сервисом проверь доступ к сайту:

```bash
curl -sI https://download.blender.org/release/Blender4.5/blender-4.5.12-linux-x64.tar.xz | head -1
curl -s https://download.blender.org/release/Blender4.5/blender-4.5.12.sha256 | head -3
```

## Известные ограничения

- Аддоны и перенос настроек Blender (preferences) ещё не реализованы, это этап 4.
- Скачивание Blender проверено на локальной имитации сайта загрузок, а не на настоящем download.blender.org (из среды разработки он недоступен). Если у сайта другой формат файла контрольных сумм, установка всё равно проходит, но без проверки суммы.
- Скачивание нельзя отменить, пока оно идёт.
- Продолжение после сбоя работает для последовательностей картинок. Видеоформат (ffmpeg) рендерится заново.
- Рендерится только активная сцена проекта.
- Файлы из File Output нод композитора пишутся по путям проекта, а не в `renders/`.
- Превью строятся для PNG, JPEG, TIFF, BMP, WebP, TGA. Для EXR превью нет.
